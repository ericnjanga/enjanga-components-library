# Home page

A presentational page with introduction, expertise, and about sections. Import `enjanga-components-library/home-page.css` alongside the core design tokens and typography. The navbar and all page shells use the same responsive container.

Supply plain text through `title`, `description`, `expertise.items`, and `about.paragraphs`. The `action` and `image` slots accept application-owned links and interactive media. Use `SectionWrapper` to add scroll effects without coupling the library to a CMS or router.

The home introduction sits lower within its hero, followed by generous section spacing that scales down with the viewport. Expertise uses stacked items separated by a short, theme-aware rule, with heading spacing from `--enj-h3-margin-bottom`, alongside vertically centered product media on desktop; compact screens keep the media in normal document flow. Section spacing is controlled by the core `--enj-home-*` tokens.

The About section keeps biography paragraphs in one readable column at every size. On wider screens, a portrait capped at 440px sits beside copy capped at 640px, with vertical alignment centered. At 1000px and below, the portrait stacks above the copy. The LinkedIn action follows the paragraphs.

Home sections use `ScrollReveal` by default. Each direct content block is observed independently, so section padding does not trigger an early reveal and stacked mobile images and copy reveal as they enter the viewport. Pass a different `SectionWrapper` to override it. `InteractiveImage` accepts native link props plus `src`, `alt`, image dimensions, and `interactionLabel`; routing comes from `LinkProvider`. Modified clicks, downloads, and new-tab links retain native behavior. Regular clicks navigate immediately; the ripple never delays navigation.

For standalone usage import `interactive-image.css` or `scroll-reveal.css`. Home page CSS includes both; case studies page CSS includes scroll reveal. Content remains visible without JavaScript, without IntersectionObserver, and when reduced motion is requested.


## Figma hover variants

InteractiveImage’s default `product` variant and its `portrait` variant show a clear image at rest. Hover and keyboard focus add 5px blur, a 50% black overlay, and the exported translucent circular CTA. All three variants follow the cursor while it remains inside the image; labels are centered at rest and for keyboard/touch use. Case study media uses the opposite `case-study` variant. Touch devices show the action without requiring a hover; reduced motion removes transitions and ripple animation.

Review all three under **External Components / InteractiveImage / Comparison**.


### Scroll reveal regression coverage

ScrollReveal tests verify that padded sections observe their content blocks,
that one block entering view does not reveal its offscreen sibling, and that
enabling reduced motion reveals pending content and disconnects the observer.
Existing tests cover server rendering, unsupported browsers, one-time reveal,
and observer cleanup.


### Initial pause and route replay

ScrollReveal holds each intersecting block hidden for 450ms, then runs its reveal.
Hidden states apply immediately; entering animation retains the existing easing and stagger.
Wrap the application in `ScrollRevealProvider` with the router pathname as `routeKey`.
Its early script prevents pre-hydration flashes; no-JavaScript and reduced-motion
visitors retain visible content. Route changes, remounts, and browser cache restoration
reset the reveal. Hash navigation within a route does not reset it. Tests cover the
pause, cancellation on exit/unmount, independent blocks, route returns, browser
restoration, and reduced-motion changes.
